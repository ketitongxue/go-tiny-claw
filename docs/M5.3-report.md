    ↓

## 4. ChannelAdapter 接口

```go
type InboundHandler func(context.Context, InboundMessage) error

type Adapter interface {
    ID() string
    Start(ctx context.Context, handler InboundHandler) error
    Send(ctx context.Context, target Route, msg OutboundMessage) error
}
```

`Start` 阻塞服务直到 Context 取消，退出前负责平台清理。Handler error 直接交回平台，允许拒绝的消息重试。Registry 拒绝空 ID 和重复 ID；线程安全地 lookup / 获取启动快照。

## 5. InboundMessage / Route

```go
type Route struct {
    Channel, AccountID, ChatID, ThreadID string
}

type InboundMessage struct {
    ID           string
    Route        Route
    UserID       string
    UserName     string
    ChatType     ChatType // direct | group
    Text         string
    MentionedBot bool
    ReceivedAt   time.Time
}
```

Route 的 channel/account/chat 不得为空或全空白，thread 可空。Core 不接收飞书原始 Event 或 SDK 类型。

当前飞书 Route 为 `feishu/default/<chat-id>/""`。不将飞书 topic/reply 改成独立 Session。Sender open_id 可填 UserID；事件本身没有 UserName，不为此额外联网。

## 6. SessionKey 规则

统一由 `channel.BuildSessionKey` 构建，每个值分别使用 `url.QueryEscape`：

```text
channel:feishu:account:default:chat:oc_xxx
channel:test:account:company:chat:C123:thread:123.456
```

非空 thread 才追加 thread 段。冒号、斜杠、反斜杠、百分号、空白、Unicode / 特殊字节均被稳定编码，避免标签/分隔符碰撞。SessionStore 继续对整个 ID 做 SHA256 文件寻址，不修改 Event Version 1。

## 7. Conversation Manager

- Map 以 canonical SessionKey 为 key，不以 ChatID 或 UserID 为 key。
- 每个 Conversation 只有一个 worker、64 条 bounded queue、一个实际 Session、一个 runner 和不可变 destination reporter。
- 同 Conversation 严格 FIFO；不同 Conversation 的 Session IO、Provider/Engine、Agent Run 并行。
- Map/admission 锁内不做磁盘、模型调用、审批通知或发送。
- Session 由 worker 解析一次；模型工厂失败可在下一条消息重试，但不会重新装载或丢弃已取得的 Session。

## 8. Gateway 工作流

```text
校验 message / route / channel / Context
    ↓
channel + account + message-id dedup
    ↓
approve / reject → 即时处理，不入队、不创建 Conversation
    ↓ 其余消息
group mention admission
    ↓
lookup/create Conversation → bounded enqueue → mark seen
    ↓ worker
Resume/Create Session → factory once → Append user → Agent Run
```

Dedup 上限 4096、TTL 24h；check/enqueue/remember 是原子的。Queue 满返回 `gateway.ErrQueueFull`，不 mark seen。Malformed approve/reject 仍作为控制命令消费，保持旧行为。

审批回复在 group admission 之前处理，因此群聊无 @ 的 approve/reject 仍可解除等待；普通群聊消息必须 MentionedBot。Adapter 做平台专属 identity/mention 判断，Gateway 不理解 mention placeholder。

接受后的任务使用 Gateway 生命周期，不依赖可能立即结束的 SDK callback Context。Shutdown cancel 后拒绝新输入，取消 active Run / Approval，跳过 queued messages，等待 worker 结束及 Session.Close；writer 不会在 runner 仍提交时释放。

## 9. Delivery / Reporter

- Delivery 根据 Route.Channel 查 Registry，将完整文本和状态交给 Adapter.Send。
- ChannelReporter 实现 engine.Reporter 和 approval.Notifier，没有任何平台分支或具体 reporter 类型断言。
- 保持原 `🤔 Thinking`、`🛠️ Tool Call`、`✅ Success`、`⚠️ Error` 和 final 文案。
- Session/模型/Agent 错误文案迁到 Conversation；普通发送失败仅记录 `[Gateway]` 日志，不损坏 Session。
- 审批通知发送失败必须向 ApprovalManager 返回 error 并默认拒绝，不能仅 log 后继续等待。
- Engine 的 Messaging Root Span 增加 channel/account_id/chat_type。Session ID 在 Engine 日志、Trace attributes 和 Trace 文件名中使用 SHA256 reference，不额外记录原始 ChatID/UserID。此举不脱敏任意正文/Tool args，也不修改 Durable Session facts。

## 10. Approval 迁移

- Manager、ApprovalResult、pendingApproval、危险命令策略均在 `internal/approval/`。
- Key 是实际 `SessionID + TaskID`；Request 包含 SessionID / Route / TaskID / ToolName / Args。
- Manager 仅通过 Notifier.RequestApproval 通知，不依赖 Engine 或平台 SDK。
- Gateway 每次创建 runtime 时注入绑定 Session/Route 的 approval.Service；Main/Explorer Registry 共用该 scoped middleware。
- `newSessionEngine` 不检查 mode，只根据是否提供 Service 挂载 middleware；没有 reporter 类型断言或全局 singleton。
- 先注册再通知；重复/过期 resolve 非阻塞，Context cancel、默认五分钟 timeout、通知失败和重复 wait 均拒绝并清理。
- 危险命令规则保持原样，只是预编译 regex；Human Approval 不是 Sandbox / Security Boundary。

## 13. Legacy Session 兼容策略

```text
Resume canonical key
    ↓ 仅 ErrNotFound
Resume injected legacy ID
    ↓ 仅 ErrNotFound
Create canonical key
```

`cmd/claw` 仅为 `feishu/default/无 thread` 注入旧 ChatID mapping；其他 channel/account/thread 不会继承它。找到旧 Session 就继续使用原 ID / WorkDir / pinned model / history，审批也按这个实际 ID 解析。新 Key 存在时优先新 Key；锁冲突、损坏、取消、WorkDir 错误不做 fallback 或另建 Session。无 JSONL 重写或 metadata schema migration。

## 19. 已知限制 / 停止范围

- 本轮只实现 Gateway Core + 单账号飞书迁移；未实现新平台、多平台启动、身份合并、attachment、streaming、富卡片、动态 plugin 或 M6 checkpoint。
- 队列和 dedup 仍是进程内状态；不是跨重启 exactly-once 或 durable ingress queue。成功 enqueue 代表接受，不代表 Agent 成功；失败的当前消息行为沿用旧版，不自动重跑。
- Conversation 无 idle eviction；Session writer 持有到 shutdown，Core 单 writer 依赖已有 SessionService/OS lock。
- Shutdown 等待遵循 Context 的 runner/tool/notifier；不强制释放仍在写入的 Session。自定义不响应取消的实现可能拖延关闭。固定 SDK 的 Start parked goroutine 仍需进程退出回收。
- 不重写 legacy JSONL；默认 account mapping 是装配层的受限兼容规则，不是跨平台共享。
- Session 隔离不等于文件系统隔离：WorkDir 及 Sandbox/Auth 原有边界保持不变。审批无新增身份授权机制，仍按原聊天范围生效。
- Trace reference 仅保护地址 metadata；Session、消息正文、代码、Tool Output / args 仍可能包含敏感信息。
