## 3. FileStore Fast Path 设计

- 每条路径独立 `fileSessionState`；`sync.Map` 只负责定位，不用全局 mutex 串行 Session。
- Create 验证 creation events 并完成私密临时文件 Write / Sync / Close、原子 Link、目录 Sync 后直接初始化 cache。
- 首次 Resume / cold Append 重放历史一次；正常 Append：检查文件状态 → 复制候选 Snapshot → apply/encode 新事件 → Write → Sync → Close → 发布 cache。
- `Load` 在持有 writer ownership 时返回深拷贝 Snapshot；无 ownership 的只读 Load 每次读新视图。
- 确定性 reader hook 测试：Create + 100 Append/Load **0 次**完整读取；Resume + 100 Append/Load **1 次**，不是按 wall-clock 断言。

## 4. Snapshot / Offset Cache 设计

状态保存 `loaded`、`snapshot`、`committedOffset`、`fileSize`、文件 identity / mtime、尾部 separator 标志、失败恢复标志、writer lease，均由同一路径 mutex 保护。

候选 Snapshot 复制 metadata/usage 值和 history slice；旧消息只在 Store 内不可变共享，新消息复制 Usage / ToolCalls / Arguments，外部 Load 返回深拷贝。移除通过 JSON marshal/unmarshal 拷贝完整历史的做法，避免重复处理历史 Tool Output 正文。

若 size / identity / mtime 与缓存不同，invalidate 并重新 replay/validate；中间损坏返回 `ErrCorrupted`。这只用于发现协议外变化，不是防恶意篡改的安全机制。

## 5. Crash Recovery 如何保持

- 原 replay 规则不变：最后一个 malformed/torn JSONL event 可忽略；中间损坏、无效事件版本/类型拒绝。
- 缓存同时记录实际 fileSize 与最后有效 committedOffset。下一次 Append 只在存在 torn tail 时截断至 offset，合法 final event 没有 newline 时补 separator。
- Write（含 short write）、Sync、Close 失败都不发布候选 Snapshot / Offset；同步尝试回到旧 offset 并 Sync / Close。
- rollback 自身失败则保留旧 Snapshot / Offset 和 `needsRecovery`，下一次操作先重试恢复，不把失败批次 replay 为已提交内存状态。
- 提交已经开始后不为响应 Cancel 中断 Sync / Close；磁盘一致性优先。新事件仍沿用 v1，不增加事务/commit record。

## 6. Context Propagation 修改

`Session.Append(ctx, ...)`、`RecordUsage(ctx, ...)`、`MarkCostUnknown(ctx)` 均透传调用 Context，不创建 Background。

- Demo 用户输入使用 `ctx`。
- Engine Assistant、Tool Observations、Reminder 使用 `turnCtx`。
- CostTracker 成功 Usage、缺失 Usage、Provider 失败路径均使用 Generate 的 `ctx`。
- Feishu 用户输入使用 bot execution Context `b.ctx`；shutdown 阻止新的用户事件。
- BenchmarkRunner 同步 API 并处理 Append 错误。
- 操作开始、取得 mutex 后、读/验证/编码阶段之间检查取消；已经开始的文件 commit 完成或恢复后才返回。

## 7. Turn Span 生命周期修改

主循环调用 `runTurn`，每次调用只创建一个 Turn Span，并在函数退出时 defer End 一次。移除主循环中的 Turn defer 及重复显式 End；所有正常 / 错误退出都覆盖。

`Span.EndSpan` 增加 mutex + ended 标志，第二次或并发结束不改写第一次 EndTime / Duration。三轮 Trace 测试用 `Turn-i.EndTime <= Turn-(i+1).StartTime` 验证独立生命周期，不用脆弱耗时上限。

## 8. Cross-process Writer Lock 设计

`Store.AcquireWriter(ctx, id) (SessionLock, error)`，Release 幂等。macOS / Linux 使用非阻塞 OS `flock(LOCK_EX | LOCK_NB)`，冲突返回 `ErrInUse`：

```text
session is currently in use by another claw process
```

Lock file 为 `sessions/<SHA256(SessionID)>.lock`，0600，拒绝 symlink / 非普通文件。OS 在进程退出 / SIGKILL 后自动释放；文件本身保留，禁止依赖文件存在判断占用，也不删除其 inode。

SessionService 在 Create / Resume 前取得 ownership，失败释放；Session.Close 阻止后续 mutation、清理 Service cache 并释放锁。Demo 所有退出路径 Close；Feishu worker 从首次激活持有至退出，关闭完成先释放再报告 workers.Done。低层直接 Store mutation 没有 lifecycle lease 时仍取得操作级 OS 锁。

同进程 path mutex 与 OS lock 职责分离。MemoryStore 提供对应的进程内 lifecycle lease；其他平台的文件 mutation 明确拒绝，不静默降级为无锁写入。

## 9. Delete / Read-only CLI 行为

- `claw session delete <active-id>`：即使通过另一个 FileStore 或进程调用，也必须获取独占锁；失败明确报 currently in use，不删 JSONL。
- Session 自身持有 writer 时，同一 Store 的 Delete 也拒绝。
- 停止 runtime、释放 ownership 后 Delete 成功；仅删除 Session，不删除 WorkDir / 代码 / Trace / lock inode。
- `claw sessions` / `claw session show <id>` 不获取 writer lock；读取完整事件前缀，末尾 torn line 按恢复规则处理。show 仍只输出 Metadata / Usage，不打印敏感聊天正文。

## 12. Benchmark 结果

命令：`go test -bench=FileStore -benchmem ./internal/sessionstore`。环境 macOS / darwin arm64 / Apple M3。每个 sample 对固定 100 / 1000 条历史消息追加一条工具输出大小的消息，包含 fsync；fixture reset 不计入 timer / allocations。Benchmark 若 fast path 读取历史则直接失败。

最终回归观测：

| 历史消息 | ns/op | B/op | allocs/op |
|---|---:|---:|---:|
| 100 | 3,580,368 | 13,753 | 24 |
| 1000 | 3,314,570 | 87,744 | 24 |

耗时受磁盘 Sync 波动影响，不作为 SLA；确定性的 0 / 1 full-read 测试才证明不按历史大小重复 replay。history slice 复制使 B/op 随消息条数增长，不宣称总 Append 成本为严格 O(1)。

## 14. 已知限制 / 停止条件

- 只支持合作的 single-writer process ownership，不实现多个进程同时写同一 Session，也不提供网络文件系统 / 分布式锁保证。
- 锁不是安全边界；同一 OS 用户或 LocalExecutor 可绕过协议修改文件。size / identity / mtime 检测不是文件完整性认证。
- FileStore 持有完整历史 cache；message-slice 复制仍为 O(消息条数)，Load 的深拷贝、CLI 的只读 replay、内存 / 磁盘使用未设 quota / cache eviction。
- 普通文件 I/O / fsync 不可由 Context 中途抢占；取消发生在已经开始的提交期间时，完成或恢复提交优先。
- JSONL v1 没有批次事务或额外 durable acknowledgement；突然掉电 / 严重磁盘故障下只能恢复可解析的完整事件前缀，不承诺跨多 Event batch 的全有或全无。rollback 无法完成且进程随后崩溃时，不能凭 v1 日志辨别完整但未获调用方确认的记录。
- Tool request/result 之间崩溃或 cancel 可留下未完成工具链，保留 M5 拒绝推理的行为，不自动重跑有副作用的工具。
- Session locks 不保护 Provider/Auth/OAuth refresh；未调整这些模块的多进程限制。
- 飞书 Close 先取消，worker 真正退出才释放锁；不合作的任务可能延迟释放，CLI 进程退出仍由 OS 释放。
- 真实模型 / 飞书 / Ctrl+C 人工体验等待验收；不自动启动外部账号任务、不自动提交或推送代码。
