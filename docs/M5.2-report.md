## 2. 新 Prompt 架构

```text
AGENTS / SYSTEM / APPEND_SYSTEM / Skills
                ↓
      ResourceLoader + Project Identity / TrustStore
                ↓
           PromptResources
                ↓
         PromptService ← Runtime / Language / Plan
                ↓
Tool Registry → PromptComposer
                ↓
 PromptState (Sections / Hashes / Sources / Content / Counts)
                ↓
       ContextBuilder → Provider
```

主要实现：

- `internal/context/sections.go`：固定顺序、验证、render、hash、metrics。
- `internal/context/composer.go`：纯函数式组装；`builtin.go`：独立内置 Core / Explorer / Plan components。
- `internal/context/prompt_service.go`：Engine 唯一 `PromptSource` 契约的实现，选择资源、角色、语言与组件。
- `internal/context/resources.go` / `resource_path.go` / `skill.go`：资源布局、发现、canonicalization、有界读取与 diagnostics。
- `internal/project/identity.go` / `trust.go`：Git/worktree 边界与用户级 Trust Registry。
- `internal/agenthome/home.go`：Config / Resource 共用 CLAW_HOME 路径解析，避免依赖环。
- `cmd/claw/prompt_commands.go`：离线 trust / prompt debug；`main.go`：启动 preflight 与统一 Registry 装配。
- `internal/eval/benchmark.go` / `cmd/bench/main.go`：注入同一 PromptSource 与 language。

AgentEngine 不解析 AGENTS/SKILL/SYSTEM，不知道资源路径或 Tool Guidelines 的语义；本次没有改动 `internal/engine/loop.go`。

## 3. Prompt Section 列表

固定为：`core`、`tools`、`rules`、`user_context`、`project_context`、`skills`、`runtime`、`plan`、`addendum`。

空 Section 不输出；core 不额外包装，其余使用 `<name>…</name>` 边界。所有文本内容转义，保留 Markdown/code 换行；属性中的引号/换行独立转义。未知或重复 Section 名拒绝。所有九个 Section（含空值）都有 SHA256，`SectionHash(name)` 可读取；未实现 Session Prompt History / Diff。

## 4. PromptComposer 改造

`PromptInput` 接收 Tool metadata、ContextFile、Skill metadata、Runtime/Plan 文本和有来源的 Addendum；不访问磁盘、Registry 或 Config。输出 `PromptState` 同时保留 ordered Sections 与 provider-compatible Content。`Sources` 仅供本地 debug，不进入 Trace。

默认 Core 保持简短；语言偏好移到 runtime，新增 Config `language`，缺省 `zh-CN`。默认 Plan 内容迁移为独立 component，仍在 Main 的 plan Section，Explorer 不启用。SYSTEM 覆盖 Core 后仍有实际 Registry 与 Explorer 运行时角色。

## 5. Tool Prompt Metadata 设计

沿用本地 STEP 2 的 `internal/promptinfo.Tool`，与 `schema.ToolDefinition` 分离；`tools.ToolPromptMetadata` 为别名，可选接口为 `PromptAwareTool.PromptMetadata()`。

read_file、write_file、edit_file、bash、spawn_subagent 均提供简明 Summary / Guidelines。Registry 以实际注册名为准，按名称排序，普通工具回退到 Definition.Description；不复制 JSON 参数 schema。Composer 合并 runtime guidelines 与当前 Tool guidelines，trim 后精确去重。补测普通 Tool 不实现可选接口仍能正常执行。

## 6. Main / Explorer Prompt 差异

| Registry | 动态 tools/rules | Plan |
| --- | --- | --- |
| Main | read_file / write_file / edit_file / bash / spawn_subagent | 按开关 |
| Docker Explorer | read_file / bash | 无 |
| Local Explorer | read_file | 无 |

移除 Bash 后其对应 Summary/Guideline 自动消失。离线 Prompt CLI 与实际 Session 共用 Main/Explorer Registry builders；不重复维护一份调试用工具清单。自定义 SYSTEM/AGENTS/Skill 仍可能在自然语言上提及其他工具，但这不会授予工具或权限，不能靠 Prompt 过滤实现安全。

## 7. Skill Lazy Loading 实现

- 只发现当前 WorkDir `.claw/skills/**/SKILL.md`，由 Trust 门禁控制，不实现用户级、父目录、远程 Skills。
- `Skill` 无 Body：Name、Description、FilePath、BaseDir，另有 ReadPath。
- YAML header 有界至 16 KiB；name 1–128 字符且不含控制字符，description 1–2048 字符。兼容 quoted/multiline frontmatter。解析错误不回显原始 YAML，单个坏 Skill 仅告警并跳过。
- Prompt 只输出 name / description / canonical location / workspace-relative read_path；不用新工具，复用现有 read_file。relative references 从 canonical SKILL.md 所在目录解析，再转成工作区相对路径；不扩大现有绝对路径/越界限制。宿主 location 不直接传给 Docker Bash。
- 字典序路径加载，同名保留先有效项、后续告警拒绝；canonical file path 去重。内部文件 symlink 可用，外部拒绝；嵌套目录 symlink 不遍历。
- 12 个 Skill 分别替换为大型正文后，PromptState 完全相同；大型正文不影响 System Prompt 大小。正文按需读入后仍作为普通 Tool Output 进入 Session 和 ContextBuilder，并不绕过预算。

## 8. AGENTS 层级与优先级

用户 `<CLAW_HOME>/AGENTS.md` → Git Repo Root → 较近祖先 → 当前 WorkDir。每层 override 优先于普通 AGENTS；坏 override 不回退。越接近当前目录的规则语义优先，并保留 path / scope 来源。

最近 `.git` 目录或 regular gitfile 作为边界，不执行 git、不跟随 linked worktree 的 gitdir。非 Git 只读 WorkDir，不扫描任意父级 AGENTS。只接受对应作用域内 regular file，canonical path 去重；内部文件 symlink 可用，外部告警跳过。Global Agent Home 必须独立于整个 Context Root，防止父级指令通过 symlink 读取全局资料。

## 9. SYSTEM / APPEND_SYSTEM 优先级

- Core：已信任 Project `.claw/SYSTEM.md` > User `SYSTEM.md` > Builtin。空 SYSTEM 也覆盖，不误用空字符串表示不存在。
- Addendum：User `APPEND_SYSTEM.md` → 已信任 Project `.claw/APPEND_SYSTEM.md`，最后输出，保留来源。
- Main / Explorer 都可覆盖 Core；tools/rules/runtime/plan 与 Explorer 只读角色不被替换，Provider/Schema/Sandbox/Approval 不受影响。
- AGENTS/SYSTEM/APPEND 限制 1 MiB。坏 AGENTS 产生 warning 并跳过；存在却不可读/越界/非 regular/超限的 SYSTEM 或 APPEND 为 error，Build 拒绝继续，不静默 fallback。缺失可选资源正常。

## 10. Project Trust 设计

Registry：`<CLAW_HOME>/trusted-projects.json`，`{"trusted":["canonical-root"]}`。精确匹配 canonical Git root / 非 Git WorkDir；从 nested cwd trust 即信任同一 repo root，linked worktree 各有 root。JSON 使用现有有界/拒绝重复字段解析，文件 0600、拒绝 symlink/非普通文件，原子保存。

未信任时加载 AGENTS/override；SYSTEM、APPEND、Skills 仅探测存在，不读正文/metadata，发出含 `claw trust` 的明确告警。坏 Registry fail closed，仅警告并禁用项目高权限资源，不阻断正常 AGENTS/用户资源。

更新使用独占 `.lock` 目录避免合作进程 read-modify-write 丢操作，冲突明确报错；崩溃残留需人工确认后清理。Trust 是路径授权，不是签名、沙箱、内容审核或自动撤销机制；同路径替换项目仍保留授权。单次 Run 内不热更新，revoke 不取消任务或清除历史 Skill Output。

## 11. 新增 CLI

```bash
claw trust [-workdir path]
claw trust status [-workdir path]
claw trust revoke [-workdir path]
claw prompt show [-workdir path] [-agent main|explorer] [-sandbox auto|docker|local] [-plan]
claw prompt render [-workdir path] [-agent main|explorer] [-sandbox auto|docker|local] [-plan]
```

新命令 WorkDir 默认 `.`；Agent 运行默认仍为 `workspace`，调试时明确传相同路径。show 不输出正文，仅 Section / Source / bytes / estimated tokens / counts。render 显示敏感性警告后输出完整内容。命令不加载 Auth/Model 状态、不调用模型、不连接 Docker/Feishu，也不创建 Session/Trace。

启动入口在服务/模型调用前做资源 preflight；每次 Run 再加载最新资源与 Trust。`-check-config` 保持原来的离线配置检查语义，不扫描 Prompt Resources，可用 `prompt show` 检查后者。

## 16. 已知限制

- 信任是路径级，不是签名或文件内容级；未信任 AGENTS/override 仍能注入指令。没有 strict trust_mode。
- canonical 路径检查不防恶意宿主并发 symlink/rename/hardlink；本轮不强化 OS 文件系统隔离。
- 只加载启动 WorkDir 的祖先 AGENTS，不动态扫描工具访问的子树，不兼容 CLAUDE.md。
- Skills 仅当前 WorkDir、本地、已信任；无 user/ancestor/remote/marketplace/load_skill；嵌套 symlink 目录不遍历。
- SYSTEM 只替换 Core；自定义指令可能与生成规则语义冲突。未实现 --system-prompt / --append-system-prompt。
- 单次 Run 固定 Prompt；下一 Run/Resume 才重载，已有 Session 中读过的 Skill 正文不因 revoke 消失。
- Section hashes 未写入 Session Prompt diff；token metrics 是 heuristic，不是官方 tokenizer；Tool Output/Session/Trace 隐私机制保持原有边界。
- 未做真实模型选择/真实 Feishu/真实浏览器 OAuth 验收；等待人工验收，不自动开始 M6。
